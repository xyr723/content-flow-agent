# GUI MVP 设计

## 背景

当前项目已经具备内容模型、平台 Skill 协议、SkillGateway、最小 workflow 和测试。用户希望在此基础上先完成一个带 GUI 的完整最小 demo，再按模块补齐细节内容。

已确认的界面方向是「运营工作台」：一个屏幕展示内容输入、目标平台、平台草稿、校验提醒、人工审核和模拟发布报告。GUI 可见文案默认使用中文。

## 目标

交付一个本地可运行、可演示、可解释架构的 GUI MVP：

- 用户能在页面中看到一份原始内容包。
- 用户能选择或看到 5 个目标平台：公众号、知乎、小红书、哔哩哔哩、抖音。
- 系统能生成每个平台的差异化草稿。
- 页面能展示校验结果、人工审核状态和模拟发布结果。
- GUI 使用现有 workflow 和 Skill 边界，不绕过核心模型。

## 非目标

- 不实现真实平台发布。
- 不接入账号、Cookie 或平台风控相关能力。
- 不引入复杂多轮 Agent 循环。
- 不做完整素材编辑器。
- 不做多用户、权限、数据库或云端部署。

## 界面结构

MVP 使用单页工作台布局，分为四个区域。

### 顶部操作区

职责：

- 展示产品名称「内容流转助手工作台」。
- 提供主要动作：导入内容、保存草稿、生成平台草稿。
- 展示当前 demo 的核心说明。

首版行为：

- 「生成平台草稿」触发一次本地 workflow。
- 「保存草稿」可作为静态按钮或后续扩展点。
- 「导入内容」首版不接文件系统，只保留入口。

### 左侧流程导航

职责：

- 用固定步骤表达 workflow：输入、平台、校验、发布。
- 帮助演示者解释系统不是循环式 Agent，而是确定性单向流程。

首版行为：

- 当前步骤可高亮。
- 不要求多路由页面跳转。

### 中央内容与平台草稿区

职责：

- 展示结构化 `ContentPackage`：标题、正文、图片素材、视频素材、发布模式。
- 展示 5 个目标平台卡片。
- 展示每个平台的 `PlatformDraft`，体现平台差异。

首版平台差异：

- 公众号：偏长文标题、摘要、正文排版、配图顺序。
- 知乎：偏问题感标题、逻辑分段、知识型标签。
- 小红书：偏种草标题、话题标签、封面建议。
- 哔哩哔哩：偏视频标题、简介、分区提示、视频标签。
- 抖音：偏短标题、简介、话题、封面文案。

### 右侧审核与报告区

职责：

- 展示校验统计：草稿数、提醒数、失败数。
- 展示每个平台的校验结果。
- 展示人工审核动作。
- 展示模拟发布报告。

首版行为：

- `manual_review` 模式展示待审核状态，不直接发布。
- `mock` 模式展示模拟发布成功、模拟链接和提示信息。
- 校验错误不阻断其他平台展示，但会在对应平台报告中明确标记。

## 前端实现边界

优先采用最小可运行方案：

- 使用原生 HTML/CSS/TypeScript 构建本地 GUI。
- 不引入大型 UI 框架。
- 不新增前端构建依赖；通过现有 TypeScript 编译和 Node 静态服务运行 demo。
- 首版可使用原生 HTML/CSS/TypeScript 组件化组织。
- 页面数据先使用内置示例内容包。
- GUI 调用现有 workflow 函数，不复制业务规则。

推荐文件边界：

- `src/gui/demo-data.ts`：示例内容包和平台注册配置。
- `src/gui/app.ts`：页面状态、事件绑定、workflow 调用。
- `src/gui/render.ts`：把 workflow 结果渲染成界面。
- `src/gui/styles.css`：工作台视觉样式。
- `src/gui/index.html`：GUI 入口。
- `scripts/serve-gui.mjs`：本地静态服务，服务 HTML、CSS 和编译后的 JS。
- `tsconfig.gui.json`：GUI demo 的 TypeScript 编译配置。
- `src/skills/platform-skills.ts`：5 个平台 Skill 的统一导出或注册辅助。

## 后端与核心模块边界

现有核心模块继续作为 GUI 的业务来源：

- `ContentPackage` 表达输入内容。
- `PlatformSkill` 定义平台能力协议。
- `SkillGateway` 注册和调用平台 Skill。
- `runContentPublishWorkflow` 执行草稿生成、校验、审核和发布。

需要补齐的核心能力：

- 将通用 `MockPlatformSkill` 拆出或补充为 5 个平台差异化 Skill。
- workflow 返回结果需要足够支撑 GUI 展示校验与发布报告。
- planner 首版可保留 stub，不作为 GUI 的必需入口。

## 数据流

首版 GUI 数据流：

```text
内置示例内容包
  -> 注册平台 Skills
  -> SkillGateway
  -> runContentPublishWorkflow
  -> WorkflowResult
  -> 渲染平台草稿、校验提醒、审核状态、模拟发布报告
```

人工审核模式：

```text
ContentPackage.publishMode = "manual_review"
  -> 生成草稿
  -> 校验草稿
  -> 返回 review_required
  -> 页面展示待审核
```

模拟发布模式：

```text
ContentPackage.publishMode = "mock"
  -> 生成草稿
  -> 校验草稿
  -> 返回 mock_published
  -> 页面展示模拟链接和报告
```

## 错误处理

- 未注册平台：页面展示明确错误，不吞掉异常。
- 草稿必填字段缺失：对应平台显示失败或错误提示。
- 非阻塞建议：显示为提醒，不阻止其他平台结果。
- 单个平台发布失败：只影响该平台报告，不影响其他平台展示。
- GUI 运行异常：顶部或右侧报告区展示可读错误信息。

## 测试策略

核心行为优先测试，GUI 做轻量验证：

- 单元测试 5 个平台 Skill 的 `adapt`、`validate`、`publish`。
- workflow 测试覆盖 `manual_review` 和 `mock` 两种模式。
- GUI 渲染测试覆盖：平台草稿数量、中文按钮文案、校验提醒、模拟发布报告。
- 本地验证命令至少包括 `npm run typecheck` 和 `npm test`。

## MVP 验收标准

- 运行本地命令后能打开 GUI 工作台。
- 首屏可见内容输入、5 个平台、平台草稿、校验提醒、审核动作和模拟发布报告。
- 页面可见文案使用中文。
- 点击「生成平台草稿」后能基于 workflow 结果更新页面。
- `manual_review` 模式不模拟发布，只显示待审核。
- `mock` 模式显示模拟发布结果。
- 新增平台仍通过 `PlatformSkill` 注册，不修改 GUI 主流程。

## 后续模块补齐顺序

1. 最小 GUI demo：本地页面、内置数据、调用现有 workflow。
2. 平台 Skill：补齐 5 个平台的差异化适配和校验。
3. 审核与报告：完善审核状态、校验统计、发布报告。
4. Planner：把自然语言指令转换为 `ContentPackage` 配置。
5. 预览细节：增强不同平台的预览样式和素材展示。
